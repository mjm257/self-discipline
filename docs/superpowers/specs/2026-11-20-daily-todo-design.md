# 每日自律 TODO · Android MVP 设计

首版服务于机主本人。在 Home 上把注意力带回当天计划，在进入自选应用时给用户一次说明使用目的的机会。以本地自用 APK 为首轮交付。验收手机为 iQOO Z10 Turbo+ V2507A。测试时记录系统实际 Android API 和 ROM 版本。

## 可行性与权限

用户选择本应用作为默认桌面后，系统进入 Home 时呈现今日页。解锁也可能恢复锁屏前的应用。遵守 Android 10 起的后台启动限制。未选择默认桌面时，从可见应用图标进入同一套 TODO 功能。

| 能力 | 用户授权或平台接口 | 失效或未授权 |
|---|---|---|
| Home | MAIN、HOME、DEFAULT，另设可见图标入口。API 29+ 请求 HOME 角色，旧系统打开默认桌面设置 | 普通启动；提供恢复系统桌面的入口 |
| 前台识别 | 用户开启 AccessibilityService，系统以 BIND_ACCESSIBILITY_SERVICE 绑定。仅取 TYPE_WINDOW_STATE_CHANGED 的包名，不访问节点、事件文本或按键 | 权限页提示，TODO 正常运行 |
| 应用上方提问 | 启用前在应用内解释用途，跳转 SYSTEM_ALERT_WINDOW 特殊授权；仅在用户明确选择的目标上显示 TYPE_APPLICATION_OVERLAY | 移除窗口、显示失效状态；重新授权后于下次有效进入恢复 |
| 应用列表 | 当前用户可启动应用，按 LAUNCHER 意图声明 queries | 搜索或手填包名；确认身份、安全性之前规则不生效 |
| 本地数据 | Room、DataStore，禁用系统备份及设备迁移；导出用系统文件选择器 | 本地写失败可重试 |

## 选择和复用

已选择从 GPL-3.0 Olauncher v6.9.17 派生。曾比较轻量 Compose Launcher 方案，但当时审查的候选缺少明确的代码复用许可。保留上游许可证、来源与作者说明。从 MainViewModel、MainActivity 及其 helper 提取 LauncherApps 枚举、用户配置、启动应用、包变化回调、Home intent 分发。统一使用新的 applicationId，与原桌面并存。使用独立图标；移除上游壁纸联网任务、设备管理、用量统计、隐藏应用等超出范围的入口、服务与授权。验收以最终合并 Manifest 为准。

## 页面和状态

首次进入先展示用途，机主设置并验证自定紧急 PIN 后开启强制提问；引导可安全离开。额外系统授权按需开启。中文 Material 3，跟随系统字号，支持大字体和键盘滚动。今日顶部显示本地日期和完成数/总数，下方计划列表、完成勾选和新增入口。点击计划编辑或删除，删除需确认。历史按日期查看计划及回答记录。桌面提供可搜索应用抽屉及系统设置、拨号入口，系统导航始终可用。守护页列出目标、开关、问题、冷却与暂停状态。设置页管理每日问题、最少字数、提问策略、PIN、权限、隐私、恢复系统桌面及清空/导出。

冷启动、Home、从外部应用回到今日、从其他页面切回今日构成进入。Home intent 与同一次前台切换合并。已在答题时重复 Home 只保留一个问题。旋转、输入法出现、应用发起的系统授权往返均沿用当前会话。每日首次模式按设备当地日期和成功保存的 TODO_ENTRY 判定。新的一天展示新日期的计划。最低字数设置下限 15，以 Unicode 码点过滤空白后计数；过滤纯格式控制字符。两处共用计数器与提交校验，显示“已输入 n/m”，输入不足禁用提交。拦截普通返回与外部点击，落库成功再关闭，屏蔽双击。

## 守护及退出

服务维护当前目标与本次进入是否已提交。只为已启用且已验证的普通用户应用建窗。应用内部窗口切换不产生新会话。输入法和本应用悬浮窗自身的事件须区别于真正离开目标。检测到拨号、来电、系统设置、系统安全/权限界面、其他桌面、锁屏，或无法可靠识别当前窗口时立即撤窗。手填包名也执行同样的检查。无法区分前台目标的多窗口、厂商 ROM 环境优先放行。系统可以隐藏悬浮窗或停止服务，系统重新绑定时重新读取权限和规则，等下一次有效前台事件再判断。

来电打断时按目标包和问题保留草稿。恢复同一个目标可续写，成功提交才开始该应用冷却并保存 OVERLAY 回答。连续停留即便冷却结束也不再次打断。切换目标分别计算。普通暂停撤下守护窗并暂停守护 30 分钟。任一提问标题长按 5 秒、校验 PIN 后退出本次问题并暂停两类提问 30 分钟；退出不生成回答。弹窗内明确提示紧急操作。忘记 PIN 仍可用系统设置更换默认桌面、撤销守护权限；需重设时可清除本应用数据，引导说明数据损失。不得拦截系统导航、卸载或请求设备管理员。

## 工程与数据

单 app 模块。Kotlin、Compose Material 3、ViewModel、Flow、手动注入。最低 API 26，目标为当前稳定 Android 17（API 37）。依赖与 Gradle Wrapper 锁定到经实际构建验证的版本。

| 包职责 | 具体内容 |
|---|---|
| launcher | Home 入口、LauncherApps、应用抽屉 |
| ui、settings | 今日、历史、编辑、守护、设置/权限、提问 UI 与各页 ViewModel |
| guard | 无障碍事件、敏感界面过滤、前台会话、可输入的悬浮窗、权限变化 |
| domain、security | 进入策略、冷却/暂停、字符计数、PIN 校验 |
| data | Room 实体/DAO、Repository、DataStore；事务成功后通知 UI |

TodoItem 保存 id、本地日期、标题、完成标记、创建/修改时间。ReflectionRecord 独立保存 id、问题快照、答案、来源、可空目标包、提交时间与提交时本地日期。GuardRule 以包名唯一，保存显示名、开关、问题、冷却秒数、上次成功提交时间。守护回答和冷却起点同一 Room 事务写入；重复提交按会话标识去重。设置含每日问题、minChars、entryPolicy、PIN 的随机盐/慢哈希及参数、两种暂停截止时间。PIN 不进入日志、导出、草稿。提案默认每个应用冷却 15 分钟，可设为 0；草稿仅存内存，系统回收进程后可能需重填。用户显式导出 JSON 时包含计划、回答及规则，提示内容敏感。清空需二次确认，恢复到首次引导。

## 真机上的守护边界

优先完成并验证正常悬浮守护。按本次窗口变化判断，未知事件不更改设备、应用或用户的长期守护设置。判定顺序如下：

1. 息屏、Keyguard 锁定、权限失效、已知敏感系统界面或暂停生效时立即撤窗。建窗前再次核对最新事件及屏幕状态，防止旧的异步查询在来电后重新建窗。
2. 已识别为本提问窗口或其输入法交互，且本次回答会话仍有效时，保留输入、焦点和当前问题。仅看到输入法包名不足以证明用户仍在原应用。已确认目标应用内部换页时沿用本次进入。
3. 收到可归属到用户勾选目标的新前台事件，且没有敏感、冲突或未解除的未知状态时，按会话、权限、冷却和暂停规则处理。切换 A 到 B 先撤 A 的窗口，再单独评估 B。
4. 前台归属无法确认时，本次放行并保留内存草稿。仅凭超时、旧包名或解锁广播不能重建窗口。后续出现足以解除疑义的新目标事件时自动恢复正常守护；没有新证据则维持放行。

桌面辅助提问只用于本桌面掌握启动意图的路径。在守护权限缺失或对该目标的识别仍不确定时，用户从应用抽屉点开它，可在启动前回答。提交成功后为这次启动记录一次放行，守护服务恢复时沿用该次提交，即使冷却为零也避免连续提问。普通暂停、紧急暂停及敏感目标排除对辅助路径同样生效。从通知或最近任务进入且无法识别时，直接放行。系统未报告的来电小窗无法仅凭包名识别，作为 ROM 实测限制记录。

| 真机验收场景 | 预期 |
|---|---|
| 权限齐全，从最近任务进入可明确识别的目标 A | 直接显示悬浮问题 |
| 在 A 的问题中输入、收起键盘、在 A 内换页 | 不重复提问，不把输入法计为一次离开 |
| A → 来电或未知窗口 → 已重新确认的 A | 中间无覆盖，恢复 A 的草稿，提交前不启动冷却 |
| A 出现未知窗口，随后正常进入已确认的 B | 本次不确定性不影响 B，B 按自己的规则处理 |
| 从本桌面启动识别仍不确定的 A，桌面答完后服务重新识别 A | 只记录一次回答，当前启动不再弹窗 |
| 外部入口归属不明或一直没有新的前台证据 | 保持放行，不抢前台 |
