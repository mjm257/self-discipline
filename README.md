# 每日自律 TODO

在自己的手机上，按 Home 回到今日计划；准备打开指定应用时，先写下使用目的。解锁会恢复之前的前台任务，只有系统回到桌面时才呈现今日页。Android 10 及以上限制后台拉起 Activity。跨应用守护使用单独的无障碍服务及普通应用悬浮窗。

| 能力 | 如何开启 | 关闭后的体验 |
|---|---|---|
| 默认桌面 | 应用设置 → 设为默认桌面 → 在系统选择「每日自律 TODO」 | 点应用图标仍可管理计划 |
| 外部入口守护 | 阅读用途后到系统无障碍设置启用「自律应用守护」 | 从本桌面打开仍能先答再启动 |
| 在其他应用上提问 | 系统「显示在其他应用的上层」授权；无障碍与悬浮窗需分别开启 | 外部入口直接放行 |
| 应用选择 | 在「守护」选择可启动的个人应用，或填写包名；提交前验证身份 | 不授予全量包查询权限 |
| 导出 | 从「设置」选择本地 JSON，经文件选择器指定位置 | 计划与回答保存在应用私有存储 |

## 页面与规则

首次设置 4–12 位数字紧急 PIN。今日页显示完成进度，可以新增、改名、删除和勾选计划。历史按日期查看计划、每日回答和守护回答。「应用」抽屉支持搜索并启动应用。设置页提供权限状态、隐私、清空及导出。

- 今日页默认每次进入提问，可切换为每日首次。问题和入口策略在设置中修改。每日提问与应用守护均为满 15 个非空白字符即可提交，应用不设字数上限。回到今日页会提问，旋转、输入法切换及授权页往返保持当前会话。
- 在「守护 → 添加守护应用」为各应用分别设置问题、开关、冷却秒数。默认 900 秒。桌面抽屉先问再启动；从通知、链接和最近任务进入时，确认目标后悬浮提问。回答入库后开始计时；保持前台不会定时弹窗，重新进入且冷却结束才提问。
- 普通暂停只作用于应用守护。任一问题长按标题满 5 秒并输入紧急 PIN，暂停两类提问 30 分钟。设置页可以恢复系统桌面；忘记 PIN 可以从系统更换桌面、关闭授权。系统设置中清除应用数据会删除本机记录并重置 PIN。
- 来电、锁屏、敏感或无法识别的窗口优先放行。内存草稿在返回相同应用和问题后可续写，进程被回收时会丢失。服务等待系统重新绑定；强制停止、卸载、关机或 ROM 后台限制均会中止守护。

## 工程与数据

键盘收起及无法归属的面板会中断前台判断。服务等待新的目标应用事件，保留同一次进入已经保存的回答。真实返回本桌面、锁屏或确认另一个应用进入前台后，下次进入会重新检查规则。模拟器的系统键盘会把输入窗口报告为全屏，守护结合当前输入法和本窗口实际获得焦点的编辑框辨认它。

桌面提交产生的启动放行凭据限该目标一次、有效期 30 秒。已确认进入其他应用或返回本桌面会使旧凭据失效。守护服务短暂失联时，同一进程最多保留 30 秒的上次会话，重新收到同一目标的前台事件才会沿用。若服务失联期间离开又返回同一目标，系统可能没有提供中间的事件；进程被回收或超过时限后，也可能在冷却为零时再次提问。

基于 Olauncher v6.9.17，Apps.kt 从上游 LauncherApps 路径适配应用枚举、组件启动与包变化监听。GPL-3.0 来源与作者见 [上游说明](docs/upstream/Olauncher-README.md) 和 [许可证](LICENSE)。

| 文件（app/src/main/java/dev/daily/todo） | 职责 |
|---|---|
| Apps.kt、MainActivity.kt | 桌面、系统角色/授权、应用启动及生命周期 |
| DailyModel.kt、DailyApp.kt、Plans.kt、Preferences.kt | ViewModel 与中文 Material 3 页面 |
| DailyDatabase.kt、Store.kt、StorePolicy.kt | Room 实体/DAO/事务、DataStore、PIN 与字数策略 |
| GuardService.kt、GuardSessions.kt、OverlayManager.kt | 前台事件、权限变化、草稿、可输入的悬浮问题 |

TodoItem 按本地日期保存计划。ReflectionRecord 保存提交时的日期、来源、目标包、问题与回答快照，以会话 ID 防重。GuardRule 保存各应用问题、冷却与上次提交时间。桌面提问放行记录与回答同事务保存；PIN 使用随机盐与 PBKDF2 慢哈希。应用不请求 INTERNET，不读取无障碍节点或输入事件，不上传数据。导出包含个人回答，请自行保管。

## 安装包

用手机打开 [下载 Android 调试 APK](https://github.com/mjm257/self-discipline/raw/refs/heads/launcher-baseline/downloads/daily-todo-debug.apk)，安装后从「每日自律 TODO」图标开始。也可在下方使用源码自行构建。

## 构建与运行

安装 JDK 17、Android SDK Platform 36 和 Build Tools 35；targetSdk 为 37，最低支持 Android 8.0（API 26）。配置 ANDROID_HOME 或在 local.properties 设置 sdk.dir。从仓库根目录运行：

~~~powershell
.\gradlew.bat testDebugUnitTest assembleDebug
adb install -r app\build\outputs\apk\debug\app-debug.apk
adb shell am start -n dev.daily.todo/.MainActivity
~~~

macOS/Linux 使用 ./gradlew。Gradle 首次运行需要联网解析构建依赖。用于真机自测的调试包带调试签名。

## 真机验收单

以 iQOO Z10 Turbo+（V2507A）为首轮验收设备。连接手机后用 adb shell getprop ro.build.version.sdk 记录实际系统 API。先保留原桌面，再按以下步骤测试。

| 验收项 | 操作与预期 |
|---|---|
| 入门和恢复 | 不授予特殊权限也能完成 PIN 设置、管理计划。选择默认桌面后按 Home，最后用系统「默认应用 → 桌面」恢复 |
| 今日页 | 分别输入 14、15 个非空白字符，混入换行和全角空格；仅达标可提交，返回/点外部不能取消。保存后在历史看到一条记录 |
| 进入策略 | 冷启动、外部返回、切页、Home；输入一半旋转、开关键盘。切每日首次策略，跨日再检查 |
| 计划与日期 | 新增、编辑、勾选、取消、删除；切换历史日期并重启核对数据及进度 |
| 两条守护路径 | 选一款第三方普通应用，冷却置零。从抽屉答完再启动，应只问一次；离开再从最近任务进入，双授权时显示悬浮窗 |
| 冷却与隔离 | 给 A 设置 15 分钟、B 设置 0。A 提交后在冷却内重进放行；一直停留不反复问。分别修改问题并检查历史快照 |
| 例外与紧急 | 输入草稿后收到来电或进入系统设置，窗口应让开；回到 A 续写。长按不足 5 秒、错误 PIN、正确 PIN，核对两种暂停范围和 30 分钟有效期 |
| 断开权限 | 撤销任一权限后外部入口放行；重新启用后下一次有效事件恢复。桌面内启动目标仍能提问 |
| 资料与故障 | 导出 JSON 检查历史与规则；二次确认清空后回到引导。重复提交、锁屏、进程重启、ROM 小窗和分屏单独记录 |

Android 11+ 限制包可见性，未能验证的包、系统预装应用、桌面、拨号与输入法不能加入有效守护。ROM 可能限制桌面角色、特殊授权或隐藏悬浮窗；请以系统设置实际显示为准。仅凭窗口事件元数据无法保证辨认所有来电小窗、分屏和多屏场景，未知事件放行，后续有效事件恢复。详细触发条件见 [设计与验收场景](docs/superpowers/specs/2026-11-20-daily-todo-design.md)。

## 本次验证记录

在 API 35 / Android 15 x86_64 独立模拟器安装调试包，使用另一个普通测试应用验证跨应用流程。已实际验证首次 PIN、14/15 字提交边界、旋转后草稿、计划增改勾选与删除确认、日期历史、覆盖安装保留数据。切换 HOME 角色后按系统 Home 可回到今日提问。

双授权关闭时，本桌面仍能先问再启动。双授权开启且冷却为零时，桌面提交只写一条 LAUNCHER_ENTRY。离开后从外部再进入会显示悬浮问题，输入 9 字后切换系统设置会撤窗，返回同一目标能续写到 18 字；提交只产生一条 OVERLAY 记录。展开键盘直接提交后持续停留不重问。标题长按超过 5 秒可进入 PIN 验证，错误 PIN 被拒绝，正确 PIN 后 Home 和外部守护均暂停，不产生回答记录。

12 项 JVM 单元测试通过；调试 APK 签名验证通过。V2507A 的真实来电、厂商小窗、省电回收和权限菜单仍需在该手机上按上述清单验收。
